# 전공 구분 재조사와 학생 중심 흐름 제안

2026-09-09. 학생용 페이지가 아니라 개발·기획 기록이다. 이 문서의 제안은 아직 전체 아키텍처 구현 완료를 뜻하지 않는다. 요청받은 초기화·초안 저장·버튼 연결·입학연도 선택 수정과 구분한다.

## 1. 다시 확인한 자료와 결론

### 학교 공개 자료

- [천안 학사종합안내](https://www.dankook.ac.kr/web/kor/%ED%95%99%EC%82%AC%EC%A2%85%ED%95%A9%EC%95%88-)가 현재 연결하는 것은 version 13.0이다. 이전 작업의 version 12.0은 당시 확인 기록으로 남기며 현재 연결본으로 취급하지 않는다.
- [현재 공개 PDF](https://www.dankook.ac.kr/documents/d/kor/2026-1-_-260119-pdf?download=true)는 139쪽이며 2026-2학기 내용을 포함한다. 101쪽(인쇄 52쪽)의 일반학과 기준은 주전공만 이수할 때 심화 63학점 이상, 다전공 병행 시 주전공 42학점 이상, 복수전공 42학점 이상, 부전공 21학점 이상이다. 30쪽(인쇄 18쪽)의 2026학번 식품자원경제학과 행도 63/42를 확인한다. 두 표를 직접 시각 대조했다.
- 같은 자료 72쪽(인쇄 60쪽)은 식자경 5개 트랙·15개 모듈과 과목 구성을 설명한다. 이 페이지에는 트랙30과 복수·부전공 학적 인정 관계의 전체 세부조건은 없다.
- [학칙 2026-05-07 개정본](https://rule.dankook.ac.kr/service/law/lawFullScreenContent.do?historySeq=3506&seq=7) 제28조의4는 전공교육과정 안의 모듈 운영을, 제46조는 소속 전공 외 복수·부전공 등을 다룬다. [시행세칙 2026-06-15 개정본](https://rule.dankook.ac.kr/service/law/lawFullScreenContent.do?historySeq=3510&seq=8)의 일반 모듈 규정을 학과의 세부 트랙 규정으로 임의 대체하지 않는다.

### 제공 PDF의 반증도 보존

비공개 `2. 2026학년도 식품자원경제학과 모듈형 트랙제 교육과정 (2).pdf`는 기존 보존본과 SHA-256이 같음을 대조했다. 전체 추출 텍스트와 관련 4·5·6쪽의 이미지·각주·도식을 다시 확인했다. 원문 파일은 편집하거나 업로드하지 않았다.

- 4쪽은 학과 입학생을 심화전공·트랙형전공·다전공으로 나눈 운영 예시를 갖고 있다.
- 5쪽은 ‘복수전공 또는 부전공 또는 트랙형전공’이라는 문구와 별도 갈래 도식을 갖고 있다.
- 같은 5쪽은 학과 트랙30에 필수과목12~15를 더하는 복수전공 예시(42~45), 융합 트랙30에 필수12를 더하는 복수전공 예시(42)를 설명한다. 따라서 30을 복수42에 단순히 더해 72로 계산하면 안 된다.
- 부전공21을 채웠다는 사실만으로 트랙30 조건이나 트랙명 표기를 자동으로 충족한다고 볼 수 없다. 타 학과 트랙30만의 독립 학적·증명서 인정은 이번 공개 조사로 확정하지 못했다.

**판단:** 현재 화면은 학적상 전공 구분과 트랙 이수 목표를 하나의 선택지 집합으로 섞어 놓았다. 학생에게는 두 질문을 분리하는 것이 타당하다. 다만 ‘학교 규정상 독립 트랙형전공이 절대 불가능하다’고 단정하거나 기존 외부 트랙 사용자를 부전공으로 자동 변환할 근거는 부족하다.

## 2. 서비스의 중심 과업

학생은 ‘내가 이미 들은 수업으로 이 트랙에서 무엇이 남았고, 다음에 무엇을 들으면 되는지’를 알고 싶다. 트랙제 설명과 추천은 이 판단을 돕고, 학기 계획은 결과 이후의 선택 행동이다. 행정 용어 선택 자체를 첫 과제로 만들 필요는 없다.

| 제품 판단 | 내용 |
|---|---|
| 현재 행동 | 본인의 이수 이력으로 선택 트랙의 남은 과목을 확인한다. |
| 병목 | 전공 구분과 트랙 선택의 혼합, 추천 기준 혼합, 결과 이후 행동 단절. |
| AI 필요 여부 | 필수 아님. 설문 점수·모듈 충족·학점·겹치는 과목은 검증 가능한 규칙으로 계산한다. |
| 포함 | 안내, 최소 내 정보, 과목 입력, 트랙 확정/비교, 남은 과목, 선택 계획, 기록·신청 안내. |
| 제외 | 학교 신청 대행(공식 접수와 별도), 로그인·동기화(현재 불필요), 취업 확률(근거 없음), 자동 트랙 확정(학생 결정). |
| 기존 결함 처리 | 초기화·임시 저장·잘못된 버튼 목적지는 이번 승인된 수정으로 해결. |
| 완료 판단 | 아래는 제안 흐름. 학적·트랙 데이터 모델을 바꾸는 추가 구현과 검증은 별도로 진행해야 함. |

## 3. 권장 여정

```text
트랙제 안내 · 이미 알면 바로 시작
        ↓
나의 정보
        ↓
트랙을 정했나요?
 ├─ 정했어요 → 선택 트랙 → 수강 이력 입력 ───────────┐
 ├─ 관심부터 찾을래요 → 관심 설문 → 후보 선택 → 수강 이력 ┤
 └─ 들은 과목으로 찾을래요 → 수강 이력 → 트랙 비교 → 선택 ┤
                                                     ↓
                               내 트랙 현황 · 남은 과목 · 다음 수강 후보
                                                     ↓
                                   학기 계획 · 필요할 때만
                                                     ↓
                             기록 보관 · 학과 신청/문의 준비 · 다음 방문
```

설명 페이지는 신규 학생의 자연스러운 시작점이지만 반드시 읽어야 하는 통과 단계로 만들지 않는다. 이미 아는 학생과 재방문자는 진단·내 결과로 바로 들어간다. 세 가지 분기는 입력을 반복하는 별도 서비스가 아니라 같은 결과로 합류하는 경로다.

### 나의 정보는 어디까지 묻나

- 학과 학생: 식품자원경제학과 주전공임을 자동 반영한다. ‘심화·트랙형·다전공’ 용어를 먼저 고르게 하지 않는 방향을 권장한다.
- 타 학과 학생: 식자경을 복수전공/부전공으로 이수하는지, 아직 정하지 않았는지 구분한다. 그다음 트랙 목표를 별도 질문으로 둔다. ‘아직 미정’은 학적 기준 미정이며 부전공 기본값으로 바꾸지 않는다.
- 입학연도: 이번 수정은 최근 10년(2017~2026) 선택, 미선택, 이전 연도 직접 입력을 제공한다. 학번별 필수가 필요한 결과에는 미선택 상태를 그대로 표시한다.
- 다른 전공 병행 여부: 본 학과 학생의 전체 전공학점·계획 조건에 실제로 필요할 때 묻는다. 모르는 상태에서 모두 63 또는42로 판정하지 않는다.
- 목표 졸업 학기·학기당 수강량: 계획 화면에서만 묻는다. 진단부터 하려는 학생에게 요구하지 않는다.
- 이름·학번 전체·연락처: 계산에 필요하지 않으므로 수집하지 않는다.

## 4. 미정 학생의 두 추천은 다르게 작동해야 한다

| 경로 | 답할 질문 | 먼저 보여줄 것 | 하지 않을 것 |
|---|---|---|---|
| 관심 설문 | 무엇을 배우고 싶나요? | 관심이 맞는 이유·관련 수업·다른 후보 | 수강 이력으로 흥미 점수를 덮어쓰기 |
| 이수 이력 비교 | 지금 이력에서 무엇을 더 이수하면 되나요? | 이미 채운 모듈, 추가 과목·학점, 선택 트랙과 겹치는 과목 | 이수가 쉽다는 이유로 관심까지 맞는다고 설명 |

관심과 이수 접근성을 한 숫자로 합치지 않는다. 동점이면 공동 후보로 보여주고 학생이 선택하게 한다. 선택하지 않은 후보는 자동으로 현재 트랙이나 학적을 덮어쓰지 않는다.

현재 `recommendationEngine.ts:100–102`는 추가 과목 수·학점에 전체 전공학점 보완분도 포함한다. 새로운 ‘늦게 발견한 트랙’ 기능에서는 **트랙 자체에 필요한 추가 이수**와 **전공 전체에서 필요한 학점**을 분리해야 한다. 그렇지 않으면 트랙과 관계없는 졸업학점 때문에 여러 트랙의 유불리가 똑같아 보일 수 있다.

## 5. 놓치기 쉬운 부분과 보완

1. **이미 거의 채운 다른 트랙**: 현재 트랙 결과 아래에 ‘지금 이수한 과목으로 함께 확인할 트랙’으로 제안한다. 이미 충족, 추가 이수 적음, 겹치는 과목이 많음을 구분한다. 실제 학교 신청·인정을 완료했다고 표현하지 않는다.
2. **복수 트랙의 추가 부담**: 각 트랙의 남은 과목을 단순 합산하지 않고 중복 과목을 한 번만 센다. 트랙을 하나 더 선택했을 때 추가되는 과목·학점을 보여준다.
3. **완료·수강 중·계획 구분**: 현재 충족은 완료 과목만 사용한다. 수강 중 과목을 마쳤을 때의 예상은 별도 미리보기로, 계획 과목은 일정으로 표시한다.
4. **과목명 변경·동일교과목·목록 밖 학점**: 학생이 직접 바로잡을 수 있게 한다. 필수의 조건부 대체와 일반 전공학점 인정은 별개로 처리한다.
5. **신입생·0과목**: 잘못 입력한 상태로 몰지 않는다. ‘아직 들은 과목 없음’으로 진단하고 기초·첫 수강 후보부터 안내한다. 관심 설문은 선택이다.
6. **졸업 가능성과 트랙 완료 가능성**: 구분한다. 전자는 교양·전체학점·학번 기준 등 추가 정보가 필요하다. 트랙 과목만 보고 전체 졸업을 가능으로 판정하지 않는다.
7. **실제 개설과 남은 학기**: 모듈 조건뿐 아니라 개설 확인, 선이수조건, 수강 여유를 계획에서 확인한다. 예전 개설 이력과 앞으로 확정된 시간표는 다른 근거다.
8. **신청까지의 연결**: 마지막에 학과 신청 공지·준비 자료·문의로 이어준다. ‘관심 트랙을 저장’한 것과 ‘학교에 신청’한 것을 같은 완료 상태로 표시하지 않는다.
9. **재방문**: 홈에서 내 결과 이어보기, 수강 중 과목 완료로 바꾸기, 계획 수정으로 바로 들어간다. 기존 정보와 보관 기록을 다시 입력하거나 지우지 않는다.

## 6. 화면 책임과 문구

- 안내: ‘트랙이 무엇이고 무엇을 할 수 있는가’. 공식 영상·원문은 선택해서 열기.
- 정보·이력: ‘내가 어떤 상황이고 무엇을 들었는가’. 직접 선택 기본, PDF 보조.
- 비교: ‘어떤 기준으로 무엇을 고를 것인가’. 들어온 목적에 따라 관심/이력 기준 유지.
- 결과: ‘선택 트랙에 무엇이 남았는가’. 남은 과목을 먼저, 조건별 상세를 다음에.
- 계획: ‘그 과목을 어느 학기에 들을 것인가’. 초안 보존, 수정·기록 보관.

문구 틀: ‘[트랙명]에서 남은 과목을 확인하세요’, ‘이 과목을 들으면 두 트랙의 조건을 함께 채울 수 있어요’, ‘현재 이수 내역으로 함께 살펴볼 트랙이 있어요’. 구체적인 숫자는 실제 계산 결과가 있을 때만 채운다.

## 7. 구현 시 지킬 데이터 경계

`소속/전공 구분`, `희망 트랙`, `수강 이력`, `관심 답변`, `계획 초안`, `확정 계획`, `보관 기록`은 구분해서 저장한다. 비교를 위한 임시 조건은 확정 프로필을 바꾸지 않는다. 이전 저장값의 외부 track-major를 복수/부 중 하나로 조용히 변환하지 말고, 필요하면 기존 기록을 유지한 채 현재 전공 구분만 다시 확인한다.

새로고침·이전 이동·다른 후보 선택·0과목·이미 충족·복수 트랙·개설 미정·저장 실패·초기화 취소를 대표 시나리오로 검수한다. 사용자 완료율 개선은 실제 학생 관찰이 없으므로 아직 측정된 결과가 아니다.
