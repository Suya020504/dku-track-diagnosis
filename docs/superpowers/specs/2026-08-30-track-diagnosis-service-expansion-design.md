# 단국대학교 식품자원경제학과 트랙진단 서비스 확장 설계

- 작성일: 2026-08-30
- 상태: 사용자 검토 대기
- 구현 기준: GitHub `main` `544f21c`
- 보존 대상: 현재 로컬 `138ce95` 기반 미커밋 개편 전체
- 대상 사용자: 식품자원경제학과 입학생과 타 학과 다전공 학생

## 1. 목표

이 서비스는 학생이 트랙제의 목적을 이해하고, 자신의 소속과 이수 경로에 맞는 규칙을 선택한 뒤, 현재 이수 과목 기준의 진행도와 졸업까지의 실행 계획을 공식 근거와 함께 확인하도록 돕는 참고 진단 서비스다.

서비스의 핵심 결과는 `공식 이수 확정`이 아니다. 다음 네 가지를 구분해 제공한다.

1. 현재 입력 기준 충족 상태
2. 부족한 필수·모듈·전체 전공학점
3. 목표 졸업 학기까지의 계획상 가능성
4. 학교 또는 학과에 공식 확인해야 할 항목

## 2. 승인된 제품 결정

- 식품자원경제학과 입학생과 타 학과 복수·부전공 학생을 모두 지원한다.
- 졸업 가능성은 `가능/불가능`으로 단정하지 않는다.
- 결과 상태는 `현재 충족`, `정규학기 내 계획상 가능`, `수강량 조정 필요`, `추가 학기 필요 가능성`, `공식 확인 필요`로 구분한다.
- 이수 과목은 직접 선택이 기본이다.
- PDF 불러오기는 직접 선택값을 채우는 선택 기능이며, 자동 확정하지 않는다.
- 관심 적합도, 현재 이수 접근성, 졸업 전 계획 가능성을 하나의 종합점수로 합치지 않는다.
- 기능을 늘리기 전에 사용자가 막힌 순간, 필요한 근거, 다음 행동, 저장·복구를 함께 설계한다.
- 디자인과 이미지는 판단을 돕는 용도로 사용하며 장식만을 위한 요소는 만들지 않는다.
- 입학연도와 2026 교육과정 적용 여부가 확인되지 않으면 공식 완료 판정을 만들지 않는다.

## 3. 근거와 적용 경계

### 공식 공개·확보

- 단국대학교 2026 학사종합안내의 5개 트랙·15개 모듈·과목 구성
- 단국대학교 학칙의 모듈형 교육과정 정의
- 2026-1·2 실제 개설학기와 공식 교과목번호

### 사용자 제공 자료 기반 잠정 규칙

- `2026학년도 식품자원경제학과 모듈형 트랙제 교육과정(최종안).pdf`
- 세부 이수학점, 필수과목, 학생 유형별 운영 예시

해당 PDF는 공식 공개 원문 URL과 적용 학번이 확인되지 않았다. PDF에만 있는 세부 규칙은 `provided-final-plan` 상태로 기록하고, 결과에 근거 상태를 노출한다.

### 공식 확인 필요

- 필수·트랙·전체 전공학점 사이의 중복 인정 방식
- 타 학과 학생의 경제학 트랙 최소학점
- 복수 트랙 신청·인정 방식
- 동일·대체 교과목과 과거 교육과정 인정
- 현장실습·인턴십·캡스톤의 전공학점 포함 여부
- 미래 반복 개설 규칙

## 4. 사용자가 서비스를 찾는 순간

### 신입생·저학년

- 트랙제가 무엇인지 이해한다.
- 관심 트랙을 찾는다.
- 앞으로 들을 과목의 방향을 잡는다.

### 트랙을 정한 재학생

- 선택 트랙 진행도를 확인한다.
- 부족한 모듈과 다음 과목을 찾는다.
- 다음 학기 계획을 저장한다.

### 졸업 임박 학생·타 학과 학생

- 자신의 소속과 이수 경로에 맞는 규칙을 확인한다.
- 목표 졸업 학기까지의 계획 가능성을 검토한다.
- 학과에 확인할 질문을 정리한다.

## 5. 과정 구분

### 필수 과정

1. 현재 목적 확인
2. 학생 소속 확인
3. 이수 경로 확인
4. 이수 완료 과목 직접 선택
5. 선택 내용 검토·확정
6. 경로별 기본 진단
7. 결과 근거와 다음 행동 확인

### 조건부 필수

- 트랙형전공: 진단할 트랙 선택
- 트랙을 모르는 트랙형전공 학생: 직접 선택 또는 관심 설문
- 졸업 계획 분석: 현재 학기, 목표 졸업 학기, 학기당 수강 가능량 입력
- PDF 사용: 자동 인식 결과 검수

### 선택 과정

- PDF로 직접 선택값 채우기
- 관심 기반 트랙 탐색
- 다른 트랙 비교
- 학기 계획 저장
- 과거 진단과 변화 비교
- 결과 내보내기

관심 설문·PDF·졸업 계획 입력을 모든 학생에게 강제하지 않는다.

## 6. 상태 전이

```text
목적 미설정
→ 목적 확정
→ 소속·입학연도·이수 경로 확정
→ 이수 완료 과목 직접 선택 중
→ 입력 검토 완료
→ 트랙형전공이며 트랙 미정이면 관심 설문 또는 직접 선택
→ 학생이 진단 트랙 확정
→ 기본 진단 완료
→ 비트랙 경로의 선택적 관심 추천
→ 졸업 계획 분석 선택
→ 실행 계획 저장
→ 다음 학기 재방문·과목 상태 갱신
```

각 상태는 다음 계약을 가진다.

- 진입 조건
- 완료 조건
- 저장할 데이터
- 수정 가능한 이전 단계
- 대응하는 주소
- 새로고침·뒤로가기 후 복원 상태
- 실패 시 가능한 다음 행동

## 7. 도메인 모델

### 사용자 목적

```ts
type ServiceGoal =
  | "learn-track-system"
  | "find-track"
  | "check-progress"
  | "plan-graduation";
```

목적은 저장·복원하고 최초 다음 행동을 결정하지만 계산 규칙을 바꾸지 않는다.

### 학생 소속과 이수 경로 분리

```ts
type StudentAffiliation = "department-student" | "external-student";

type StudyPath =
  | "advanced-major"
  | "track-major"
  | "department-with-other-major"
  | "double-major"
  | "minor";

type StudentProfile = {
  goal: ServiceGoal;
  affiliation: StudentAffiliation;
  studyPath: StudyPath;
  entryYear?: number;
  curriculumRuleVersion: "2026-provided-final-plan";
  ruleApplicability:
    | "student-confirmed"
    | "officially-verified"
    | "reference-only";
};
```

허용 조합은 규칙 테이블로 제한한다.

| 소속 | 허용 경로 |
|---|---|
| 학과 입학생 | 심화전공, 트랙형전공, 다전공 이수 |
| 타 학과 학생 | 복수전공, 부전공, 트랙형전공 |

### 과목 상태 분리

```ts
type CourseSelectionStatus = "completed" | "in-progress" | "planned";

type CourseSelectionRecord = {
  courseId: string;
  status: CourseSelectionStatus;
  plannedTerm?: "next" | "following" | "later";
};
```

- `completed`만 현재 충족 판정에 사용한다.
- `in-progress`와 `planned`는 계획 결과에만 사용한다.
- 같은 과목은 한 시점에 하나의 상태만 가진다.
- 낙제·철회·재수강·학점 미인정·성적 미확인 과목은 `completed`가 아니라 별도 검수 항목으로 둔다.

### 교육과정표 밖 인정 전공학점

```ts
type AdditionalMajorCredit = {
  id: string;
  label: string;
  credits: number;
  status: "student-entered" | "officially-verified";
  note?: string;
};
```

현장실습·인턴십·캡스톤·과거 동일교과목처럼 현재 목록만으로 계산할 수 없는 전공학점을 입력할 수 있게 한다. `student-entered` 값은 전체 진행도 참고 계산에 포함하되 공식 확인 필요 항목을 함께 반환한다.

### 규칙 근거 상태

```ts
type RequirementEvidenceStatus =
  | "official-public"
  | "provided-final-plan"
  | "project-derived"
  | "official-review-required";
```

모든 규칙은 기준연도, 원문, 확인일, 적용 대상, 근거 상태를 가진다.

## 8. 학생 유형별 계산 계약

| 소속 | 경로 | 트랙 | 문서 기준 | 서비스 판정 |
|---|---|---:|---|---|
| 학과 입학생 | 심화전공 | 불필요 | 필수 18 + 기타 전공 45 = 63 | 필수와 전체학점 분리 |
| 학과 입학생 | 학과전공 트랙 | 필수 | 5개 모듈별 6, 트랙 30, 전체 63 | 필수·트랙·전체 분리 |
| 학과 입학생 | 푸드바이오경제 | 필수 | F/H/I 개별 3·합계 15, M 8, N+O 7, 전체 63 | 복합조건 분리 |
| 학과 입학생 | 다전공 이수 | 불필요 | 필수 18 + 기타 전공 24 = 42 | 필수와 전체학점 분리 |
| 타 학과 학생 | 복수전공 | 불필요 | 필수 18 + 기타 전공 24 = 42 | 필수와 전체학점 분리 |
| 타 학과 학생 | 부전공 | 불필요 | 필수 무관, 전공 21 | 트랙·필수 미적용 |
| 타 학과 학생 | 학과전공 트랙 | 필수 | 트랙 30 + 트랙 밖 필수 | 트랙별 고유학점 계산 |
| 타 학과 학생 | 푸드바이오경제 | 필수 | 트랙 30 + 트랙 밖 필수 12 = 42 | 복합조건과 고유학점 계산 |

### 필수과목 규칙 변형

첨부 PDF 내부에는 `모듈 C 필수`, `B 경제학기초 필수`, `B·C 필수`, 6쪽 별표 6과목이 함께 존재한다. 따라서 하나의 공식 규칙으로 확정하지 않는다.

```ts
type RequiredCourseRuleVariant = {
  id: "starred-six-2026" | "department-confirmed";
  courseIds: string[];
  requiredCredits: number;
  evidence: RequirementEvidenceStatus;
  allowsOfficialCompletion: boolean;
};
```

현재 참고 계산의 `starred-six-2026`은 PDF 2쪽 밑줄과 6쪽 별표가 일치하는 다음 6과목을 사용한다.

- B-2 통계학기초
- C-1 미시경제학
- C-2 소비자경제학
- C-3 거시경제학
- F-1 식품유통경제학
- H-1 마케팅조사분석

B-1 경제원론은 이 변형에서 개별 필수 표시가 없어 제외한다. 다만 `starred-six-2026`은 `provided-final-plan`이며 `allowsOfficialCompletion: false`다. 학생의 적용 학번과 학과 확인 규칙이 확보되기 전에는 필수조건을 채워도 `참고 계산상 충족·공식 확인 필요`로 반환한다.

### 문서 모순 처리

- 심화전공은 `18 + 45 = 63`을 적용한다. 문서 괄호의 `18 + 39`는 산술 오류로 기록한다.
- 타 학과 경제학 트랙은 트랙 밖 필수 18학점으로 최소 고유 48학점이 된다. 문서의 42~45 범위와 모순되므로 자동 완료 판정을 금지하고 `official-review-required`를 반환한다.
- N 식품영양은 상세 목록 기준 4과목으로 관리한다.
- M/N/O 세부 코드 밀림은 모듈명 기준 M/N/O로 정규화한다.

## 9. 진행도 엔진

엔진은 하나의 `passed`만 반환하지 않는다.

```ts
type PathProgressResult = {
  requiredProgress: RequirementProgress | "not-applicable";
  trackProgress: TrackProgress | "not-applicable";
  totalMajorProgress: CreditProgress;
  reviewItems: ReviewItem[];
  status:
    | "current-input-satisfied"
    | "reference-calculation-satisfied"
    | "incomplete"
    | "official-review-required";
};
```

계산 원칙:

- 모든 과목 ID를 중복 제거한다.
- A 학문기초 교양은 63·42·21 전공학점에 포함하지 않는다.
- 등록된 과목의 고유 전공학점과 `AdditionalMajorCredit`을 합산해 전체 전공학점을 계산한다.
- `student-entered` 추가학점을 사용한 충족 결과는 `reference-calculation-satisfied`와 확인 필요 항목을 반환한다.
- 필수와 트랙에 겹친 과목은 각 조건 충족에는 사용하지만 실제 취득학점은 한 번만 합산한다.
- 트랙 30학점 총량만으로 모듈별 요구를 대체하지 않는다.
- 기본 진단은 학생이 확정한 `targetTrackId` 하나만 판정한다. 다른 트랙은 추천·비교 엔진에서 각각 독립 계산하며 하나의 통합 완료 여부로 합치지 않는다.
- 알 수 없는 과목은 제거하지 않고 확인 필요 항목으로 반환한다.

## 10. 추천 엔진

추천은 세 축을 독립적으로 반환한다.

### 관심 적합도

- 관심 설문 응답
- 진로·활동 관심 키워드
- 점수가 비슷하면 복수 후보로 안내

### 현재 이수 접근성

- 현재 완료 과목이 각 트랙의 모듈 조건에 기여하는 정도
- 부족한 최소 고유 과목 수
- 충족한 모듈과 부족한 모듈

### 졸업 전 계획 가능성

- 목표 졸업 학기까지 남은 기간
- 학기당 수강 가능량
- 실제 확인된 개설학기
- 필수·트랙·전체학점의 최소 과목 조합

서비스는 하나의 `종합 1위`를 만들지 않는다. 다음 결과를 별도로 제시한다.

- 관심에 가장 가까운 트랙
- 현재 가장 빨리 채울 수 있는 트랙
- 졸업 계획을 만들 수 있는 트랙과 계획을 만들지 못한 이유

같은 트랙이 두 개 이상의 축에서 선두면 `여러 기준이 같은 방향을 가리킴`으로 설명한다. 서로 다른 트랙이면 학생이 기준별 결과를 비교하도록 하며, 숨은 가중치로 균형 순위를 만들지 않는다.

### 결정적 최소 과목 조합

후보 조합은 다음 사전식 우선순위로 한 번만 정렬한다.

1. 모든 적용 하드 조건 충족
2. 새로 들어야 하는 고유 과목 수 최소
3. 새로 들어야 하는 고유학점 최소
4. 목표 졸업 학기 안에 확인된 개설학기로 배치 가능한 조합 우선
5. 더 이른 권장 학년·학기 우선
6. 과목코드 오름차순으로 동률 해소

같은 입력과 같은 규칙 버전은 항상 같은 결과를 반환해야 한다.

## 11. 졸업 계획 엔진

### 입력

- 현재 학기
- 목표 졸업 학기
- 학기당 최대 전공과목 수
- 계절학기 사용 여부
- 완료·수강 중·예정 과목
- 실제 개설학기 데이터

### 처리

1. 부족한 필수 조건 계산
2. 모듈별 최소 과목 조합 계산
3. 전체 전공학점 부족 계산
4. 인정 가능한 선택 전공과목 후보와 입력된 추가 인정학점을 반영
5. 같은 과목의 중복 기여를 유지하면서 고유학점은 한 번만 합산
6. 실제 개설학기와 남은 학기 연결
7. 학기당 수강량 안에서 배치
8. 과목으로 특정할 수 없는 선택 전공 부족학점은 `unallocatedElectiveCredits`로 반환
9. 배치하지 못한 과목과 이유 반환

### 출력 상태

- 현재 충족
- 정규학기 내 계획상 가능
- 수강량 조정 필요
- 추가 학기 필요 가능성
- 공식 확인 필요

자동 계획에는 정규학기만 사용한다. 계절학기는 공식 개설 데이터가 확보되기 전까지 사용자가 기록하는 참고 계획과 확인 필요 항목으로만 유지한다.

미래 학기 개설은 보장하지 않는다. 2026 실제 개설정보는 최근 패턴에 따른 참고 배치에만 사용한다.

## 12. 이수 과목 입력과 PDF 보조

### 기본

- 직접 선택
- 과목 검색
- 학년·학기·모듈 필터
- 선택 즉시 임시 저장
- 선택 내용 검토 후 진단 반영

### PDF 선택 기능

- 텍스트형 PDF를 학생 브라우저 안에서만 분석한다.
- PDF 원본, 학번, 이름, 성적 원문을 저장하거나 외부 전송하지 않는다.
- 분석 결과를 `matched`, `ambiguous`, `unmatched`로 구분한다.
- 자동으로 과목을 확정하지 않는다.
- 학생이 승인한 과목 ID만 기존 직접 선택값에 병합한다.
- 실패하거나 스캔 PDF이면 직접 선택 상태를 보존하고 수동 선택으로 돌아간다.
- OCR, 포털 자동 연동, 서버 업로드는 MVP에서 제외한다.
- 파일 시그니처와 MIME이 PDF인지 확인한다.
- 최대 10MB·50쪽으로 제한한다.
- 암호화·손상 PDF는 분석하지 않고 직접 선택으로 전환한다.
- 파싱은 Web Worker에서 수행하고 15초를 넘으면 중단한다.
- 파싱 중 네트워크 요청을 만들지 않는다.
- 원문 텍스트와 ArrayBuffer를 분석 종료 즉시 메모리에서 해제하고 로그에 남기지 않는다.

실제 포털 수강내역 PDF 표본이 확보되기 전에는 `beta` 기능으로 표시하고, 일반 PDF 내 알려진 과목명 매칭만 검증한다.

## 14. 결과에서 다음 행동으로 연결

## 16. 디자인·이미지 제작 계약

디자인은 기능 수를 보여주기 위한 장식이 아니라 다음 세 질문을 빠르게 이해시키는 역할을 한다.

1. 지금 무엇을 해야 하는가?
2. 이 결과의 근거는 무엇인가?
3. 다음에는 무엇을 해야 하는가?

### 이미지 생성 활용

- 이미지 생성은 사용자 흐름과 정보 역할이 확정된 뒤 사용한다.
- 초기에는 의미가 명확한 3개 슬롯만 별도의 가로형 디자인 레퍼런스로 제작한다.
- 트랙 구조, 학생 여정, 진행도에서 실행 계획으로 이어지는 맥락을 시각화한다.
- 학교 공식 이미지와 생성 이미지를 명확히 구분한다.
- 생성 이미지를 공식 캠퍼스·공식 교육과정 증거처럼 사용하지 않는다.
- 데이터 수치, 진행률, 과목표, 공식 로고, 작은 아이콘은 결정적 코드·기존 아이콘 라이브러리로 구현한다.
- 생성 이미지 안에 긴 한글 표·수치·공식 규칙을 넣지 않는다.
- 선택한 생성 이미지는 프로젝트 내부에 저장하고 WebP 사본, 대체텍스트, 생성 프롬프트, 용도를 기록한다.

### 초기 시각 자료 슬롯

기능 구현과 함께 다음 슬롯의 필요성을 검토한다.

- 트랙제 개념과 장점을 설명하는 학생 여정 이미지
- 과목 → 모듈 → 트랙 연결을 돕는 교육용 이미지
- 현재 진행도 → 다음 과목 → 졸업 계획 흐름 이미지

PDF·빈 상태·오류 복구는 아이콘과 명확한 문구를 우선하고, 사용자 검증에서 이해를 돕는 필요성이 확인될 때만 추가 이미지를 만든다.

각 런타임 이미지는 WebP 기준 200KB 이하를 목표로 하고, 고정 width/height, 모바일용 `srcset`, LCP 이미지 외 지연 로딩, 의미에 맞는 대체텍스트를 검증한다. 학교 공식 사진은 외부 서비스 재사용 허락과 필수 표기를 확인하기 전 배포 자산으로 확정하지 않는다.

## 19. Acceptance Tests

계산 오라클은 구현 코드에서 역산하지 않는다. `docs/data/requirement-scenarios-2026.md`에 PDF 페이지·규칙 변형·입력 과목·추가 인정학점·예상 결과를 수작업으로 기록한 최소 16개 정상·경계·모순 시나리오를 두고 테스트 픽스처가 이를 참조한다. 공식 확인 전 시나리오는 `참고 계산상 충족` 또는 `공식 확인 필요`를 기대값으로 사용한다.

### 계산

1. `starred-six-2026` 참고 변형은 정확히 6개이며 B-1은 제외한다.
2. 학번·규칙 적용이 미확인된 `starred-six-2026` 충족은 공식 완료가 아니라 참고 계산상 충족을 반환한다.
3. 타 학과 복수전공은 B-2를 포함한 참고 필수 18학점을 요구한다.
4. 부전공은 필수 0, 전공 21학점으로 독립 판정한다.
5. A 교양은 63·42·21 전공학점에 포함하지 않는다.
6. 심화전공은 총 60이면 미충족, 63이면 규칙 근거 상태에 맞는 충족을 반환한다.
7. 학과 입학생 다전공과 타 학과 복수전공은 각각 총 42와 참고 필수 18을 검사한다.
8. 학과 입학생 트랙은 트랙 조건을 채워도 고유 전공학점 63 미만이면 전체 기준 미충족이다.
9. 학과전공 트랙은 총 30이어도 하나의 모듈이 6 미만이면 미충족이다.
10. 푸드바이오는 F/H/I 개별·합산, M, N+O를 모두 검사한다.
11. 타 학과 경제학 트랙은 최소 고유 48 계산과 문서 모순을 함께 반환한다.
12. 같은 과목 ID는 실제 취득학점에 한 번만 합산한다.
13. 공식 확인되지 않은 추가 인정학점은 총학점에 반영하면서 확인 필요를 반환한다.
14. 수강 중·예정은 현재 충족에 포함하지 않는다.
15. 낙제·철회·재수강·미확인 항목은 완료로 계산하지 않는다.
16. 여러 트랙은 독립 판정한다.
17. 알 수 없는 과목은 확인 필요로 반환한다.

### 추천·계획

18. 관심·진행·계획 결과는 독립적이며 균형 종합점수를 만들지 않는다.
19. 최소 과목 조합은 정의한 사전식 우선순위에 따라 결정적이다.
20. 전체 전공 선택학점 부족분을 `unallocatedElectiveCredits` 또는 과목 후보로 반환한다.
21. 목표 졸업 학기를 넘는 과목은 정규학기 계획상 가능에 포함하지 않는다.
22. 학기당 최대 수강량을 넘는 배치를 만들지 않는다.
23. 개설학기가 맞지 않으면 확인 필요 또는 미배치 이유를 반환한다.
24. 계절학기를 자동 가능 판정에 사용하지 않는다.
25. 미래 개설을 보장하는 문구를 생성하지 않는다.

29. PDF 원본과 개인정보를 저장하지 않는다.
30. PDF 자동 매칭은 학생 확인 전 직접 선택값을 변경하지 않는다.
31. PDF 실패 후 기존 직접 선택값을 유지한다.
32. 암호화·손상·10MB 초과·50쪽 초과·타임아웃 PDF를 안전하게 거절한다.
33. 재진단은 이전 규칙 버전과 결과를 덮어쓰지 않는다.
34. 최근 12개를 초과한 진단 이력은 가장 오래된 항목부터 제거한다.

## 21. 초기 사용자 검증

구현 완료만으로 서비스 효과를 주장하지 않는다. 실제 학생이 어디에서 막히고 다음 행동으로 이어지는지 30일 동안 확인한다.

### 확인할 행동

- 학생 유형·이수 경로를 스스로 올바르게 선택하는가
- 직접 선택으로 첫 진단을 끝까지 완료하는가
- 공식 사실과 서비스 계산을 구분하는가
- 결과 후 다음 과목·학기 계획·공식 문의 중 하나를 선택하는가
- 다음 학기에 다시 방문해 과목 상태를 갱신하는가

### 초기 목표값

- 검수된 계산 시나리오 오판정 0건
- 핵심 진단 완주율 80% 이상
- 직접 선택 기준 첫 진단 중앙시간 8분 이내
- 공식 사실과 서비스 계산을 올바르게 구분한 사용자 80% 이상
- 결과 후 다음 행동을 하나 이상 저장하거나 선택한 사용자 60% 이상
- 새로고침·뒤로가기 상태 손실 0건
- 개인정보가 로그·저장소·화면 캡처에 남는 사고 0건

목표 미달 시 기능을 추가하기보다 중단 지점, 잘못 이해한 규칙, 필요 없는 입력을 먼저 수정한다.
