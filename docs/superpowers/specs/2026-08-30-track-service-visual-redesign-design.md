## 1. 재설계 목표

현재 화면의 반복적인 흰 카드, 기본 버튼, 큰 지표 묶음, 화면마다 달라지는 정보 구조를 폐기한다. 신입생이 `내 관심 트랙 찾기`를 시작하면 관심·과목·트랙·다음 학기가 하나의 플래너 경로로 점차 펼쳐지는 서비스로 바꾼다.

재설계는 제품 기능과 공식 근거를 바꾸지 않는다. 화면 표현, 정보 구조, 컴포넌트 경계, 반응형 방식과 시각 자산을 교체한다.

## 2. 사용자가 선택한 방향

### 캠퍼스 안내책자 × 학업 플래너

- 첫 화면의 주 행동: `내 관심 트랙 찾기`
- 보조 행동: `이수 과목 바로 진단`
- 메인 이미지: 캠퍼스 컴퍼스 일러스트
- 공식 캠퍼스 사진: 출처·권한 안내가 있는 보조 카드
- 전체 구조: 왼쪽 안내책자 색인 + 중앙 Compass Path Ribbon + 점진적으로 펼쳐지는 학기 플래너
- 색: 하늘색·민트, 단국 블루, 학과 녹색, 농식품 밀색
- 인상: 친근하지만 유치하지 않은 대학생용 학업 안내 도구

### 기존 화면에서 버릴 것

- 같은 크기의 흰색 둥근 카드 반복
- 첫 화면의 결과 대시보드 미리보기
- 네 개 지표를 먼저 보여 주는 결과 헤더
- 기본 브라우저 스타일 버튼과 검은 focus outline
- 한 화면에 추천·모듈·학기표·확인 항목을 모두 펼치기
- 실제 기능과 연결되지 않는 번호·뱃지·장식선

## 3. 핵심 경험

```text
랜딩
  ├─ 내 관심 트랙 찾기 (주 행동)
  │    → 관심 질문
  │    → 상위 트랙 비교·직접 선택
  │    → 학생 유형 확인
  │    → 이수 과목 선택
  └─ 이수 과목 바로 진단 (보조 경로)
       → 학생 유형 확인
       → 이수 과목 선택

결과
  → 현재 상태
  → 다음 과목
  → 세 기준 비교
  → 학기별 계획
  → 공식 확인
```

Compass Path Ribbon은 이 흐름의 실제 주소·단계와 일치한다. 클릭 불가능한 장식용 진행선으로 만들지 않는다.

## 4. 화면 체계

### 4.1 공통 App Shell

#### 데스크톱

```text
┌─────────────────────────────────────────────────────────┐
│ 학과 텍스트 워드마크               도움말  로컬 저장 상태 │
├──────────────┬──────────────────────────────────────────┤
│ 안내책자 INDEX│ 화면별 내용과 Compass Path Ribbon          │
│ 시작하기      │                                          │
│ 트랙 탐색     │                                          │
│ 자가진단      │                                          │
│ 결과          │                                          │
│ 학기 플래너   │                                          │
│ 기록·근거     │                                          │
└──────────────┴──────────────────────────────────────────┘
```

- 계정·로그인·프로필 이름을 만들지 않는다.
- 공식 seal·logo 이미지는 공개 런타임에서 사용하지 않고 텍스트 워드마크로 학교·학과를 구분한다.
- `이 브라우저에 저장됨` 상태를 계정 영역 대신 표시한다.
- 색인은 현재 주소와 상태를 반영하며 완료하지 않은 단계는 잠금 이유를 설명한다.

#### 모바일

- 왼쪽 색인을 상단의 현재 단계 제목과 하단 4개 핵심 행동으로 변환한다.
- 모든 색인 항목을 하단 탭에 넣지 않는다. `시작`, `진단`, `결과`, `계획`만 고정하고 트랙·기록·근거는 `더보기` 안에서 제공한다.
- 하단 행동이 내용이나 PDF 검수 버튼을 가리지 않도록 safe-area를 포함한다.
- 잠긴 목적지는 `잠김` 표식을 항상 보이고, 터치·키보드 선택 시 이동 없이 잠금 이유를 화면에 표시한다.

### 4.2 랜딩

#### 첫 화면

- 왼쪽 색인에서 `01 시작하기` 활성
- 중앙 상단: `내 관심을 따라, 전공 로드맵을 완성해요`
- 주 행동: `내 관심 트랙 찾기`
- 보조 경로: `이수 과목 바로 진단`
- 오른쪽 상단 30–35%: 컴퍼스 일러스트의 경로·나침반 장면
- 중앙 3단 리본:
  1. 관심 질문
  2. 트랙 탐색
  3. 학기 계획
- 하단: 비활성·부분 공개 상태의 실제 플래너 예고. `관심을 찾으면 계획표가 펼쳐져요`라고 표시한다.

#### 다음 접힘

- 5개 TrackGlyph와 실제 트랙명
- `과목 → 모듈 → 트랙` 관계를 HTML·SVG로 설명
- 공식 근거와 프로젝트 계산을 한 줄의 출처 띠로 구분
- 공식 캠퍼스 사진은 앱에 삽입하지 않고 공식 근거 페이지의 출처 정보와 원문 링크로만 안내

랜딩에는 진단 결과 퍼센트 예시나 가짜 학점 수치를 넣지 않는다.

### 4.3 관심 설문

- 왼쪽 색인은 `01 시작하기`, Path Ribbon은 `관심 질문` 활성
- 한 화면에 한 문항
- 1–5 선택지는 긴 카드가 아니라 planner scale로 표시
- 진행률은 `3 / 10`과 짧은 경로선으로 표현
- 답변은 즉시 로컬 저장
- 결과에서는 Top 3와 트랙 glyph, 정식 후보명을 사용
- 비슷한 점수는 공동 후보로 보여 주되 트랙을 학생이 직접 선택

### 4.4 학생 유형·이수 과목

- 학생 유형은 주전공/트랙형/복수/부전공을 설명 문장과 함께 세로 선택지로 제공
- 학과 학생/타 학과 학생과 이수 경로를 하나의 화면에 과밀하게 넣지 않고 2개 소단계로 분리 가능
- 과목 선택은 planner ledger 형식
  - 과목명
  - 모듈 glyph
  - 학점
  - 학년·학기
  - 상태
- 학년·학기와 모듈 색인을 빠른 그룹 내비게이션으로 제공
- 목록 상단에 `결과로 건너뛰기` 링크를 추가해 45개 체크박스 탭 순서를 단축
- PDF beta는 기본 화면 아래의 보조 섹션으로 유지

### 4.5 결과

결과는 `현재 → 다음 → 확인` 세 URL 페이지로 분산하고 색인 버튼에 `aria-current="page"`를 사용한다.

#### 현재

- 상태 문장: `보완할 조건이 있어요`, `참고 계산상 충족` 등 기존 안전 문구
- 적용 이수 경로와 근거 상태
- 필수·트랙·전체 전공 진행을 한 개의 세로 경로로 표시
- 퍼센트는 보조 정보이며 화면의 가장 큰 요소가 아니다.

#### 다음

- 다음에 들을 과목을 course sticker로 제공
- 추천 이유, 기여 모듈, 최근 개설 이력과 확인 필요를 함께 표시
- 관심·현재 진행·계획 가능성 비교로 이동

#### 확인

- 문서 충돌, 미래 개설, 추가 인정학점, 학과 확인 질문
- 공식 자료 링크와 결과 PDF 저장/인쇄

### 4.6 기준별 트랙 비교

- 세 기준은 같은 순위표에 합치지 않는다.
- `관심`, `현재 완료 과목`, `졸업 전 계획`을 표준 탭 위젯이 아닌 URL 페이지 색인으로 전환한다.
- 각 탭의 첫 후보와 근거, 다음 후보 2개를 표시
- 동일한 트랙이 여러 기준에서 선두일 때만 Compass Path가 한 방향으로 합쳐지는 애니메이션을 사용
- 가설 비교에는 `트랙형전공으로 전환한다고 가정한 비교`를 밀색 띠로 명시

### 4.7 학기 플래너

- 선택된 C 방향의 핵심 화면
- 데스크톱: 학기 열을 가로 planner로 표시
- 모바일: 학기별 세로 시간축
- 이름 있는 과목과 `전공 선택 과목 N학점 자리`를 구분
- 개설 이력 근거 배지와 미래 비보장 문구를 고정
- `일정`, `확인`, `조건 수정`을 분리
- 계획 저장은 실제 snapshot 1개 추가와 연결

### 4.8 기록·공식 근거

- 현재 구현은 진단 snapshot과 계획을 로컬에 보존하지만 별도 `나의 기록` 화면은 만들지 않았다.
- 서비스 변경 로그는 문의 화면에 남아 있으며 진단 이력 전용 UI는 후속 범위다.
- 공식 자료는 `트랙`, `모듈`, `교육과정`, `공식 근거` 네 주소로 분산
- 규칙 버전이 다른 기록은 단순 증감으로 합치지 않고 버전 경고를 표시

이 화면들의 실제 구현은 진단 이력·자료구조 후속 계획과 연결한다.

## 6. 이미지 제작과 사용

### 유지

- `campus-compass-illustration.webp`: 랜딩·설명 장면의 시각 중심
- TrackGlyph: 5개 트랙 공통 표식

### 새로 제작·정리

1. 관심 → 트랙 → 계획으로 이어지는 플래너 리본 보조 장면
2. 과목 → 모듈 → 트랙 연결 교육 이미지
3. 진행도 → 다음 과목 → 학기 계획 연결 이미지

각 이미지는 640/960/1200px WebP, 고정 크기, 대체텍스트, 프롬프트·용도 기록, 200KB 목표를 따른다. 핵심 UI 글자와 수치는 이미지에 넣지 않는다.

### 보조 공식 사진

단국대학교 캠퍼스갤러리의 천안캠퍼스 항공사진은 출처 카드에만 사용한다. 외부 재사용 권한을 확인하기 전에는 공개 배포 핵심 화면에서 제외할 수 있는 feature flag 또는 대체 이미지를 유지한다.

## 8. 전환 전략

1. 새 디자인 토큰·폰트·GuidebookShell
2. 랜딩과 공통 Compass Path Ribbon
3. 설문·프로필·과목 선택
4. 결과·추천·학기 플래너
5. 공식 자료와 진단 이력
6. 이미지 최적화·반응형·인쇄·전체 QA

각 단계는 기존 URL과 localStorage를 보존한다. 한 번에 `App.tsx`와 `styles.css`를 통째로 교체하지 않는다.

## 9. 시안에서 그대로 사용하지 않는 요소

- 생성된 가짜 단국대 로고·seal
- 생성된 사용자 이름·로그인 영역
- 시안 속 과목명·학점·학기·퍼센트
- 생성 이미지 속 작은 한글 문구
- 모든 학기를 처음부터 채운 예시 플래너
- 이미지 안의 버튼·탭·표

실제 구현은 공식 identity 이미지를 삽입하지 않고, 현재 정확한 트랙·과목 데이터, semantic HTML, 접근 가능한 버튼·입력과 텍스트 워드마크로 구성한다.

## 10. 완료 조건

- 첫 화면 10초 안에 서비스 목적과 `내 관심 트랙 찾기`가 보임
- 기존 흰 카드 그리드 인상이 사라짐
- 랜딩·설문·진단·결과·추천·계획이 같은 시각 문법을 사용
- 페이지마다 하나의 질문과 하나의 주 행동
- 공식 사실·서비스 계산·확인 필요가 색과 문구로 구분
- 데스크톱·390px 모바일에서 겹침·가로 넘침 0
- 키보드 전용 핵심 흐름 완주, 과목 목록 skip navigation 제공
- reduced motion, focus-visible, 44px 조작, H1 초점·스크롤 복원
- 기존 테스트·저장 마이그레이션·주소 복원·PDF 출력·PDF beta 회귀 없음
- 생성 이미지의 용도와 공식 이미지 비삽입·출처·권한 경계 기록
- 실제 브라우저 캡처를 시안과 나란히 비교해 material gap 0건
