## 2. 선택한 접근과 제외한 대안

### 선택: 기능 설명형 인터랙션

모션과 시각 변화는 `선택됨`, `저장됨`, `현재 단계`, `다음 행동`, `복구 가능`을 설명할 때만 사용한다. 기존 주소와 저장 상태를 유지하면서 화면 책임과 피드백을 강화한다.

### 제외: 시각 효과만 추가

hover, 떠오르는 카드, 장식 애니메이션만 추가하면 소속별 설문 중복과 저장·복구 병목이 남는다. 실제 서비스 완성도를 만들지 못하므로 채택하지 않는다.

### 제외: 로그인·클라우드 중심 재구축

기기 간 동기화는 유용하지만 현재 대표 여정의 핵심 문제가 아니다. 개인정보·운영·백엔드 범위를 크게 늘리므로 후속 과제로 남긴다.

## 3. 최종 사용자 여정과 기능 위계

### 3.1 선택 기능: 트랙제 알아보기

트랙제를 이미 아는 학생에게 강제하지 않는다. 랜딩의 보조 행동 `트랙제 먼저 알아보기`로만 진입한다.

1. 트랙제가 필요한 이유를 학생의 과목 선택 문제에서 설명한다.
2. `과목 → 모듈 → 트랙` 관계를 코드 기반 도식으로 보여준다.
3. 트랙제가 전공 방향과 학업 설명에 주는 의미를 안내하되 진로·취업을 보장하지 않는다.
4. 5개 트랙의 학습 주제와 활동을 비교한다.
5. 신청·이수·공식 확인 경계를 안내한다.
6. 마지막 주 행동 `내 트랙 현황 확인하기`로 핵심 시뮬레이션에 연결한다.

핵심 설명 문장은 다음과 같다.

> 트랙제는 과목을 단순히 많이 듣는 제도가 아니라, 관심 분야와 진로에 맞는 과목 묶음을 선택해 나만의 전공 방향을 만드는 제도입니다.

### 3.2 핵심 기능: 내 상황별 트랙제 시뮬레이션

1. 랜딩의 주 행동 `내 트랙 현황 확인하기`를 선택한다.
2. 식품자원경제학과 학생 또는 타 학과 학생을 고른다.
3. 소속에 맞는 이수 경로를 고른다.
4. 직접 선택을 기본으로 완료·수강 중·수강 예정 과목을 입력한다.
5. 목표 트랙이 없으면 5개 트랙의 현재 진행도를 나란히 보고, 목표가 있으면 해당 트랙의 상세 상태를 본다.
6. 필수·모듈·전체 학점의 현재 상태, 부족 조건, 다음 과목, 공식 확인 항목을 확인한다.
7. 결과에서 필요할 때만 관심 추천 또는 목표 학기 이수 가능성으로 이동한다.

### 3.3 추가 기능: 내 상황별 트랙 추천

목표 트랙이 없거나 다른 방향을 탐색하려는 학생만 사용한다.

1. 설문 안에서 현재 소속을 먼저 선택한다.
2. 식품자원경제학과 학생과 타 학과 학생에게 서로 다른 10문항을 제공한다.
3. 관심에 가까운 트랙과 현재 과목으로 접근하기 쉬운 트랙을 서로 다른 기준으로 보여준다.
4. 두 기준이 다르면 숨은 종합점수를 만들지 않고 학생이 직접 비교한다.
5. 트랙을 선택하면 소속을 다시 묻지 않고 해당 이수 경로로 이동한다.

### 3.4 추가 기능: 목표 학기까지 이수 가능성

현재 학기, 목표 졸업 학기, 학기당 최대 전공과목 수를 추가 입력한 학생에게만 제공한다.

- 현재 입력 기준 충족
- 목표 학기 안의 계획상 가능
- 학기당 수강량 조정 필요
- 추가 학기 검토 필요
- 미래 개설·인정 여부 공식 확인 필요

`가능` 또는 `불가능` 한 단어로 공식 판정처럼 표시하지 않는다.

## 4. 소속별 관심 설문

### 4.1 상태 계약

`InterestSurveyState`에 설문 대상을 선택적으로 추가한다.

```ts
type InterestSurveyAudience = "department-student" | "external-student";

type InterestSurveyState = {
  audience?: InterestSurveyAudience;
  answers: Record<string, InterestSurveyAnswer>;
  currentIndex: number;
  completedAt?: string;
  selectedTrackId?: TrackId;
};
```

- 새 관심 설문은 대상 선택 전에는 문항을 렌더링하지 않는다.
- 대상을 고르면 `profileDraft.affiliation`과 `interestSurvey.audience`를 함께 저장한다.
- 설문 주소는 `?view=recommendation&step=survey&audience=department-student|external-student`를 사용한다.
- 잘못된 `audience` 값은 대상 미선택 설문 화면으로 정규화한다.
- 대상이 바뀌면 관심 설문 답변·완료시각·설문 선택 트랙만 초기화한다.
- 기존 프로필, 과목, 추가학점, 진단 스냅샷, 졸업 계획은 삭제하지 않는다.
- 기존 대상 없는 설문은 자동 점수 재계산에 사용하지 않고 대상 선택 화면을 보여준다.
- 기존에 확정한 진단 목표 트랙은 설문 초기화와 별개로 보존하고, 새 설문 결과를 적용할 때만 학생 확인 후 교체한다.
- 설문에서 트랙을 확정한 뒤에는 `?view=diagnosis&step=profile&profile=path`로 이동해 소속을 다시 묻지 않는다.

## 5. 실제 서비스 인터랙션 계약

### 5.1 공통

- 페이지 전환은 주소 변경과 함께 동작하며 160~220ms 안에 끝난다.
- 단계 변경 뒤 H1로 초점을 이동하고 사용자가 현재 위치를 알 수 있게 한다.
- `prefers-reduced-motion: reduce`에서는 이동·확대 효과를 제거하고 즉시 상태만 바꾼다.
- hover는 데스크톱 보조 피드백일 뿐 기능 진입 조건이 아니다.
- 모바일은 누름, 선택, 완료 상태를 색·아이콘·문구로 함께 표시한다.
- 모든 주요 조작 영역은 최소 44×44px이다.

### 5.2 저장 피드백

- 입력 즉시 저장은 화면 상단의 지속 상태와 해당 조작 근처의 짧은 확인으로 구분한다.
- 저장 성공은 `저장됨` 상태를 1.5초 동안 강조한 뒤 기본 저장 상태로 돌아간다.
- 저장 실패는 자동으로 사라지지 않는 경고와 `다시 저장` 또는 현재 입력 유지 안내를 제공한다.
- 동일한 저장 이벤트를 여러 toast로 중복 표시하지 않는다.

### 5.3 화면별 인터랙션

| 화면 | 핵심 인터랙션 |
| --- | --- |
| 랜딩 | `내 트랙 현황 확인하기`를 유일한 주 CTA로 두고, `트랙제 먼저 알아보기`와 저장 상태 이어하기를 보조 행동으로 제공 |
| 트랙제 가이드 | 제도 의미·과목-모듈-트랙 관계·장점·5개 트랙·공식 확인을 선택적으로 읽고 시뮬레이션으로 이동 |
| 소속·설문 | 추천 기능에서만 대상 선택 후 질문은행 전환, 문항 진행 애니메이션, 답변 즉시 저장, 대상 변경 경고 |
| 과목 원장 | 행 전체 터치, 체크 즉시 상태 변화, 선택 개수 갱신, 필터 결과 빈 상태, 컨테이너 기반 행 재배치 |
| 결과 | 현재·다음·확인 URL 전환, 수치보다 상태 문장 우선, 다음 행동을 한 개의 Primary CTA로 제공 |
| 비교 | 관심·진행·계획 축을 섞지 않고 독립 페이지로 전환, 동일 선두일 때만 합류 설명 |
| 플래너 | 조건 입력 → 일정 → 확인 전환, 학기 항목의 출처 상태, 저장 스냅샷 피드백 |
| 자료 | 학업 여정 리본을 숨기고 4개 자료 탭만 사용, 외부 링크 44px 이상, 공식 근거와 프로젝트 해석을 분리 |

## 6. 랜딩 시각 구조

콘셉트는 지도형 여정을 제거한 `깔끔한 전공 탐색 홈`으로 확정한다. 지도 이미지·경로선·범례를 랜딩에서 제거하고 네 구역만 남긴다.

### 6.1 확정 카피

- 상단 설명: `단국대 학생을 위한 트랙제 안내·자가진단`
- 메인 문구: `어떤 트랙이 나한테 잘 맞을까?`
- 설명: `관심 있는 분야와 지금까지 들은 과목을 입력하면, 가까운 트랙과 앞으로 더 들어야 할 과목을 확인할 수 있어요.`
- 주 행동: `내 트랙 확인하기`
- 보조 행동: `트랙제 먼저 알아보기`
- 신뢰 안내: `자가진단 결과는 학업 계획을 돕는 참고 정보이며, 실제 인정 기준은 학과 확인이 필요합니다.`

### 6.2 네 구역

1. 히어로: 공식 DKU 로고 원본, 식품자원경제학과 표기, 메인 문구, 주 CTA, 학생 책상·강의 노트 보조 장면
2. 시작 방식: 핵심 상황별 시뮬레이션과 선택형 관심 추천의 목적 차이
3. 트랙·이용 흐름: 5개 트랙 펼침형 비교와 `소속·경로 → 과목 → 결과 → 선택형 계획` 단순 단계
4. 재방문: 저장된 진단 이어하기와 선택형 플래너 안내

DKU 로고는 `public/dku-logo.png` 원본을 HTML 이미지로 한 번만 사용한다. 생성 이미지 안에 로고를 굽거나 재생성하지 않는다.

예상 시안은 구역별 가로 레퍼런스 4장으로 확인했다. 실제 런타임에는 히어로의 책상·노트 장면만 필요한 경우 별도 자산으로 분리하고, 버튼·표·수치·한글·로고는 HTML과 원본 자산으로 구현한다.

## 10. 테스트 전략

### 10.1 테스트 우선 항목

1. 관심 탐색 시작 시 소속 선택 화면으로 이동
2. 소속별 질문 ID·문장이 겹치지 않음
3. 두 질문은행 모두 5개 트랙에 동일한 최대 기회를 제공
4. 대상 변경 시 설문만 초기화하고 과목·진단·계획 보존
5. 설문 완료 후 소속 단계를 반복하지 않고 이수 경로로 이동
6. legacy 공통 설문이 화면을 깨뜨리지 않음
7. 과목 원장 720px 이하 compact grid와 410px 이하 3열 grid
8. reduced motion에서 transition·transform 제거
9. 랜딩에 지도·경로·범례가 없고 확정 카피와 한 개의 주 CTA가 있음
10. 트랙제 가이드를 건너뛰고 시뮬레이션에 직접 진입할 수 있음
11. 자료 화면에는 학업 여정 리본이 없고 4개 자료 탭만 있음
12. 결과에서 관심 추천과 목표 학기 가능성이 추가 행동으로 연결됨

## 11. 완료 조건

- 학과생과 타 학과생 질문 문장·ID가 구분되고 각각 10문항을 완주한다.
- 트랙제 가이드는 선택 기능이며 핵심 시뮬레이션 진입을 막지 않는다.
- 랜딩은 지도 콘셉트 없이 확정 카피·주 CTA·5개 트랙·저장된 진단 이어하기를 제공한다.
- 대상 선택을 반복해서 묻지 않는다.
- 설문 대상 변경이 과목·결과·계획을 삭제하지 않는다.
- 화면마다 주 행동이 하나이며 선택·저장·완료 상태가 즉시 보인다.
- 344px부터 1920px까지 의도하지 않은 가로 overflow와 고정 UI 겹침이 없다.
- 태블릿 세로·가로와 Fold 접힘·펼침에서 같은 핵심 기능을 완주한다.
- 이미지가 장식이 아니라 화면 목적을 설명하고 모바일 크롭에서도 의미가 유지된다.
- 자료 화면은 중복 학업 여정 리본 없이 자료 탭만 제공한다.
- 공식 사실·서비스 계산·확인 필요 상태가 색과 문구로 구분된다.
- 모든 디자인 검증 게이트가 PASS다.

## 12. 남은 위험과 중단 조건

- 소속별 문구가 실제 학생에게 자연스러운지는 사용자 검증 전까지 가설이다.
- 외부 학생의 트랙형전공 적용과 인정 범위는 학과 공식 확인이 필요하다.
- 공식 캠퍼스 사진은 재사용 허가 확인 전까지 런타임 자산으로 사용하지 않는다.
- 질문 가중치가 한 트랙을 구조적으로 유리하게 만들면 출시를 중단하고 균형 테스트를 수정한다.
- 대상 전환이 기존 진단·계획을 삭제하면 출시를 중단한다.
- P0·P1 결함, 저장 손실, 잘못된 공식 완료 표현이 남으면 완료로 판정하지 않는다.
